# Silice original graphics (tilesets and objects from generated art)

Status: pipeline built (`2fc4c16` and after); Brico-Bourg redrawn; the recurring cast and the Cocket grunts have sprites. The other maps are being redrawn town by town.

The Q3 question (original art) is answered for tilesets and overworld objects: every picture is generated by Codex's image tool, then converted deterministically into Gen3 data. No ROM graphics go into `games/silice` (the primary tilesets `General` and `Building` are still Emerald's, referenced by name).

## Pipeline

| Step | Command | Writes |
|---|---|---|
| Spec | (by hand) | `games/silice/gfx/<Tileset>.ron`: features, cells, prompts |
| Generate | `cargo xtask silice gfx gen <Tileset> [<feature>...] [--jobs N]` | raw pictures `target/silice-gfx/raw/<Tileset>/` (never committed), art `games/silice/gfx/<Tileset>/<feature>.png` |
| Re-prep only | `cargo xtask silice gfx gen <Tileset> --prep-only` | the art, from the kept raw pictures |
| Build | `cargo xtask silice gfx build [<Tileset>]` | `games/silice/tilesets/<Tileset>.{ron,png}`, `games/silice/stamps/<Tileset>_<feature>.ron`, review picture `target/silice-gfx/<Tileset>.png` |
| Sprites | `cargo xtask silice gfx sprites [<NAME>...]` | `games/silice/sprites/<NAME>.{ron,png}`, review sheet `target/silice-gfx/sprites/<NAME>.png` |
| Maps | `cargo xtask --game silice studio map build` | the maps and layouts from `games/silice/edits/` |
| Look | `cargo xtask --game silice studio map render <Map> [--events]` | `target/studio/maps/<Map>.png` |

`--game silice` goes **before** `studio`: the studio must be the Silice build to know the games dir's tilesets and sprites (`studio map --game NAME` only picks a games dir). Module docs: `xtask/src/silice/gfx.rs`, `xtask/src/silice/sprites.rs`, `crates/content/build/silice/gfx.rs`.

### Tilesets

- A spec makes one **secondary** tileset (`Sil<Place>`), paired with a primary (`General` outdoors, `Building` indoors). A map using it must take **all** its secondary metatiles from it: switching a layout's secondary means redrawing every building and prop that came from the Emerald secondary.
- Each feature is `w x h` metatiles; its art is `16w x 16h` px. Each cell is one metatile, **numbered in spec order** (512 + the cells of the features before it, row by row). Append new features at the end, never resize or reorder earlier ones: scripts name metatile ids (`set_metatile`, `METATILE_*` constants), and the stamps list them.
- Cells: `.` walkable, `#` solid, `D` door (`MB_ANIMATED_DOOR`, solid as Emerald's: pushing up into it warps), or a `legend` entry (`'w': (behavior: "MB_POND_WATER", collision: 1)`).
- Transparent art shows the `ground` primary metatile (grass is `1` in `General`). When the primary has no fitting floor (`Building` has none), give the spec a floor texture feature and set `under: Some("<texture>")` on the objects: their transparent pixels show that art, tiled from the top left. `over: [rows]` draws those rows above the objects (roof edges, arches the player walks under); other rows are under them.
- **Connection seams:** a map connection draws and collides the neighbour's cells with *this* map's tilesets (Gen3 does the same). Within 7 cells of a connected edge, use primary metatiles unless both maps share the secondary; a walkable secondary cell on the edge itself is an error in `studio map build` (the player walks onto the wrong behaviour), and other secondary cells there raise a warning (wrong pictures).
- **Derived features** (no prompt): art made from other features' art (a switched-off variant, a glowing slab, an object set on a floor crop). Write the derivation in `xtask/src/silice/derive.rs` (one function per tileset); `gen` runs it after prep, so it follows its sources. Never edit derived PNGs by hand or with a scratch script.
- Palettes: the art's 8x8 tiles are clustered into 7 palettes of 15 colours. Many very different materials in one tileset cost colour accuracy; check the review picture.

### Prompts (what worked)

- Start from the spec's `style` (minimalist GBA overworld sprite, flat colours, 1-px outline). The tool appends the size: "the whole sprite is exactly W x H pixels; each pixel visible as a large square". Asking for few details is what keeps the downscale clean: detailed pictures turn to noise at 16 px per cell.
- Place what the map needs: "a door exactly in the middle of the bottom edge". A door must fall in one cell: give buildings an odd width (3 or 5) when the door is centred.
- The key colour is magenta. A feature with pink or purple in it (neon signs) uses `key: Some("00FF00")`; the prompt then asks for a green background.
- Textures (`key: Some("none")`: gravel, water, soil) are stretched to the cells: say "only 16x16 pixels, chunky details".
- Expect one or two re-generations per feature: tune the prompt in the spec, re-`gen` that feature only.
- Prep drops magenta-like fringe pixels only under the magenta key: pink art keyed on green keeps its pink. Under magenta, ask for "light coral pink (#FF8CA0, never magenta)".

### Limits met in wave 1

- **512 tiles** per secondary tileset: a town of big buildings overflows (Gris-Échec's first spec needed 979). Keep buildings small (3-5 cells wide), reuse features, check the count `build` prints.
- **Hygiene:** a 1x1 stamp whose metatile equals an extract 1x1 layout (Emerald has some at 513 and 524) fails `studio map hygiene`; order the features so a 1x1 solid feature does not land there.
- **Seams** cost space near connected edges: keep landmarks 7+ cells away from them (see Tilesets).

### Sprites (objects)

- `gfx/sprites.ron`: one Codex picture per character (front, back, left side), split by columns, scaled together into 16x32, one 15-colour palette; the walking frames are synthesized (Gen3's 9-frame order).
- An Emerald name (`MAGMA_MEMBER_M`) replaces that sprite in Silice and keeps its id. A new name (`SIL_ADRIEN`, `gfx_id` 0x100 and up) is a new graphics id: maps write `OBJ_EVENT_GFX_SIL_ADRIEN`, the build gives it the numeric id.
- The side view must face **left** (west); if a picture faces right, regenerate.

## Per-map process (the redraw)

1. Read the map's section of its chapter (`../pokemon-silice-notion-export/contenu-jeu/chapitres/NN-*.md`, `### MAP_…`: **Visuel**, the ASCII plan, warps, NPCs).
2. Render the current map (`--events`), list what does not match the source (missing landmarks, wrong materials, Emerald-only look).
3. Write or extend the spec. Keep every door, warp, sign and object position (or move them in the edits consistently; scripts name cells).
4. `gen`, look at `target/silice-gfx/<Tileset>.png`, re-`gen` what is wrong, `build`.
5. Edit `games/silice/edits/<Map>/`: the `00_create.ron` secondary, `Stamp` ops for the features, the ground legend's metatile ids (from the stamps). Remove allowances that silence nothing, add the ones the new behaviours need.
6. `studio map build` (no errors), `render`, compare with the source again; iterate.
7. Update any script constant naming an old secondary metatile id (`grep -rn "METATILE_" crates/content/src/silice/scripts`), and run the chapter's e2e test (`PKR_GAME=silice cargo test -p content --test silN_chM`).
